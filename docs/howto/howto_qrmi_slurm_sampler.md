# QRMI/Slurm Sampler

`qcsc_prefect.integrations.qiskit.qrmi.QrmiSlurmRuntime` samples one bound,
measured circuit through a Slurm allocation and a QRMI IBM Quantum Batch.
The workflow host writes QPY and JSON to shared storage. The compute node
acquires the QRMI Target, transpiles the circuit, and launches `task_runner`.
The caller receives a native `PrimitiveResult`.

## Responsibilities

| Library | Algorithm or application |
| --- | --- |
| QPY/JSON transport, Slurm submission and monitoring | Circuit construction and molecular integrals |
| Batch environment checks and compute-node Target acquisition | QPY preparation for custom gate classes |
| Transpiler hook invocation and ISA validation | Algorithm-specific transpiler passes and provenance |
| QASM payload, CLI invocation and result decoding | Postselection, SQD recovery and eigensolvers |
| Validation of every classical register's name, width and shots | Algorithm parameters and compilation budgets |

The library does not import the examples, ffSIM, PySCF, or Fulqrum.
QRMI is imported only inside the compute-node entrypoint. The HPC executor
is imported when a sampling task runs, keeping it optional for native Qiskit users.

## Installation and configuration

Install the same library revision on the workflow host and every compute node.
The workflow host also needs the executor, available through the `slurm` extra:

```bash
python -m pip install 'qcsc-prefect-qiskit[slurm]'
```

For an unpublished checkout, install the workspace dependencies from their local
directories and install `packages/qcsc-prefect-qiskit` in editable mode.
To update the library in an already validated environment without upgrading its
runtime dependencies:

```bash
python -m pip install --no-deps -e packages/qcsc-prefect-qiskit
python -m pip check
```

Retain the cluster's existing QRMI, SPANK and `task_runner` installation.
The Python selected by the CommandBlock must import the installed library.
A new CommandBlock can use these default arguments:

```python
["-m", "qcsc_prefect.integrations.qiskit.qrmi.worker"]
```

The installation also provides the `qcsc-qrmi-sampler` console script.
Configure the execution profile with `launcher="single"`, the HPC profile with
`hpc_target="slurm"`, and `slurm_qpu` equal to the runtime's `resource`.
The work directory must be readable and writable at the same absolute path on
the workflow host and compute nodes.

SPANK must acquire a Batch before Python starts. Configure the resource's
`QRMI_IBM_QCS_SESSION_MODE="batch"` on every eligible node. The worker verifies
the selected resource's mode and acquisition-token presence; it does not change
the session mode or print the token.

## Sampling

```python
from pathlib import Path
from qcsc_prefect.integrations.qiskit.qrmi import QrmiSlurmRuntime

runtime = QrmiSlurmRuntime(
    root_dir=Path("/shared/quantum-jobs"),
    command_block_name="my-qrmi-command",
    execution_profile_block_name="my-qrmi-execution",
    hpc_profile_block_name="my-qrmi-hpc",
    resource="test_heron",
)
result = await runtime.sampler([(circuit,)], shots=100)
# Equivalent supported QuantumRuntime-style call:
result = await runtime.sampler(
    sampler_pubs=[(circuit,)], options={"params": {"shots": 100}}
)
```

Each call creates a new directory and submits a new job. Sampling-task caching
and automatic retries are disabled. Calling again after a failure submits again.
`watch_poll_interval` and `timeout_seconds` are passed to the existing executor.
A monitoring timeout does not guarantee cancellation of the quantum workload.

Only one `(circuit,)` PUB is accepted. Bind parameters before calling the runtime.
The default is 100 shots when neither supported argument supplies a value.
Conflicting `shots=` and `options["params"]["shots"]` values fail before submission.
Shots must be positive integers; booleans, strings and floats are rejected.
Other options, parameter-value PUBs and PUB-specific shots are rejected explicitly.

## Compilation hooks

`prepare(circuit) -> PreparedCircuit` runs on the workflow host before QPY
serialization. It receives a circuit copy and returns a QPY-safe circuit plus
JSON configuration. The original circuit is not modified.

`transpiler="module:function"` identifies a function imported on the compute node:

```python
def transpile(circuit, target, config):
    # Return a QuantumCircuit compatible with target.
    ...
```

The hook module must be importable on the compute node. Both hooks must preserve
classical register names and widths. Treat request/config JSON as trusted input
generated by the workflow. Configuration from `PreparedCircuit.config` overrides
matching keys in `transpile_config`.

The default hook uses optimization level 1 and accepts no algorithm-specific
configuration. Every resulting non-barrier instruction is checked against the
actual Target before calling `task_runner`.

The pinned SQD example demonstrates ffSIM preparation and a dedicated compiler:

```python
from functools import partial
from examples.qrmi_sqd_validation.pr42 import prepare_sampler_circuit

runtime = QrmiSlurmRuntime(
    root_dir=Path("/shared/quantum-jobs"),
    command_block_name="poc-qrmi-command",
    execution_profile_block_name="poc-qrmi-execution",
    hpc_profile_block_name="poc-qrmi-hpc",
    resource="test_heron",
    prepare=partial(prepare_sampler_circuit, circuit_parameters=params.model_dump()),
    transpiler="examples.qrmi_sqd_validation.pr42:transpile_for_target",
)
```

Raw LUCJ QPY round trips lose ffSIM-specific Python attributes. The example
runs ffSIM PRE_INIT and expands its gates before serialization. The library
does not reconstruct arbitrary custom Python gate attributes.

## Runtime compatibility and PR #42

This facade is not a `BaseSamplerV2` implementation or a
`prefect_qiskit.QuantumRuntime` Block. It does not implement `.load()` or
workflow-host `.get_target()`. Target acquisition and compilation run inside the
allocation. The supported `sampler(..., options={"params": {"shots": ...}})`
call and `PrimitiveResult` return shape match the tested subset.

Tests use the unchanged source snapshot from commit
`2d435b19af4648cbbc5fbc6a27ff258c93817d1a`, verified by SHA-256.
They execute its actual sampler call expression. The local adapter in
`examples/qrmi_sqd_validation/integration.py` additionally returns the `BitArray`
expected by the algorithm. It injects the runtime and options instead of loading
the original Runtime Block and Prefect Variable. Its omitted-shots default is
the PR's 100,000, distinct from the generic library's 100. The H2 CLI explicitly
defaults to 100 shots.

The snapshot is a reference fixture. This does not add the Fulqrum package or
modify the original PR. Recovery and eigensolver execution remain separate.

## Migration and diagnostics

The two forwarding modules under `examples/prefect_bitcount_demo` preserve the
validated constructor and CommandBlock script path. The facade maps
`transpile_strategy="sqd-pr42"` to the example hooks.
Update the workflow and compute-node installations together: the new sender
passes `--request sampler_request.json`, which the old worker does not support.
If using an editable installation, verify its import paths on every node.

Each job retains `circuit.qpy`, schema-version-1 `sampler_request.json`,
`transpile_config.json`, `sampler.slurm`, `isa.qpy`, `transpile_report.json`,
`sampler_input.json` and the raw `result.json`. When the executor returns a
terminal result, `slurm_job.json` records it even on failure.
Both worker and caller require one PUB and validate every register's name,
width, scalar shape and shots. A zero CLI exit code alone is not sufficient.

For the complete source-checkout deployment and H2 commands, see
`examples/qrmi_sqd_validation/README_h2_slurm.md` and `README_integration.md`.

## Validation

With the example dependencies installed, run from the repository root:

```bash
PYTHONPATH=packages/qcsc-prefect-blocks/src \
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -m pytest \
  packages/qcsc-prefect-qiskit/tests/test_qrmi_slurm_runtime.py \
  packages/qcsc-prefect-qiskit/tests/test_qrmi_sqd_qpy_transpile.py \
  packages/qcsc-prefect-executor/tests/test_qrmi_sqd_slurm_poc.py -q
```

These tests replace Slurm/QRMI service calls, block network access and execute
the real QPY, transpiler, QASM and encoded-result boundaries with a fake CLI.
The two strict expected failures document raw-LUCJ QPY attribute loss.
